# UX audit record — 2026-09-05 (release goal 9)

Produced by `npm run ux:audit -- --shots docs/qa/2026-09-05`, against the real
app served by `CI=1 npx expo start --web`, with the Firebase emulator suite
running so no development error banner covers the screens.

**Coverage.** Persian and English × light and dark × 100% and 200% text, over
`/`, `/explore`, `/garden`, `/search` and `/settings/notifications` — forty
screens. Committed here is one per combination plus the three that show the
fixes most clearly; the full set is regenerated by re-running the command.

**Result: all checks pass.** Every interactive element measures ≥ 44×44 or sits
inside a tappable box that does, every text run meets 4.5:1 against what it
actually sits on, no screen scrolls horizontally, and the document direction
follows the reader's stored language in both directions.

## What the audit found, and what changed

| finding | measured | fix |
|---|---|---|
| **Every button collapsed to its label.** `Pressable style={({ pressed }) => …}` is dropped when the component also carries a NativeWind `className`, and the height was inside it | 364×30 and 364×48→30 against a 44 floor | `src/components/button.tsx` — pressed state is local state, geometry is a plain object style |
| Tab bar items sized to their content | 103×42 | `minHeight: MinTouchTarget`; the bar already had the room |
| Garden segment chips and search filter chips | 40 tall, 43 wide | min height and min width on both |
| The search field filled a fraction of its row | 250×23 in a 48pt row | `alignSelf: 'stretch'` |
| The reminder switch | 40×20 | wrapped in a 44×44 `Pressable` that toggles it |
| "Nothing to review today" as an inline action | 146×22 | `minHeight: MinTouchTarget` |
| The hero card's cover said *"an illustration for psychology"* on a grey band — a caption for a picture that does not exist | — | drawn cover: the seed mark on the topic family's tint, hidden from screen readers |
| `expo-router` warned on every launch that `seed`, `settings`, `topic`, `path` and `review` were not routes | — | the declarations name the real files; options set on them now apply |

## Known, not fixed here

- **English plurals.** `count` is a formatted display string at all 27 call
  sites, not a number, so i18next never selects a plural form: the English port
  reads "1 seeds on this device". Persian is unaffected — it does not inflect
  the counted noun — and the fix is a convention change across all 27 sites
  (a numeric `count` for selection plus a separate display variable), which is
  not a brand-assets change. Tracked in the readiness report.
