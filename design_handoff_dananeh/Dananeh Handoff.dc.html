RTL focus order
Reading order drives focus order, so in RTL the traversal runs right-to-left, top-to-bottom. The player header is one exception: close is first regardless of side, because leaving must always be the first thing reachable.
200% type
Body scales fully; titles cap at 1.6× and clamp to three lines. Buttons grow in height and never shrink their label. Answer options become full-width blocks with the indicator top-aligned at the start edge. Nothing is hidden to make room.
Reduce Motion
Every entry in the motion spec has a cross-fade or instant equivalent. The completion ring fades in fully drawn rather than animating, and the skeleton pulse stops. Read at mount and re-read on foreground.
K · 04

Redlines — three widths and 200% text

Same screen, four conditions. Only three things change across widths: the gutter, whether card metadata wraps, and the hero illustration height. Nothing is hidden and nothing reflows into a different layout — the design has one column at every phone size, by choice. The 200% frame is annotated with its scroll boundary rather than trimmed to fit: pretending a doubled type size costs no vertical space would make the redline useless.

Gutter
20 below 430pt, 24 at and above. Cards go edge-to-edge within the gutter; nothing bleeds to the screen edge except the tab bar and banners.
Vertical rhythm
12 between cards in a group, 22 between groups, 32 before a section header. Player blocks use a strict 24 so every block starts at the same y.
Safe areas
Bottom CTA sits 26–28 above the safe-area inset, never on it. The tab bar is 76 border-box plus the home-indicator inset (96 at 200% type). The repo currently sets BottomTabInset = {ios: 50, android: 80} — Android already fits, iOS must change 50 → 76, or the labels lose 26pt and clip at large type.
At 200%
Hero illustration drops 96→70 and metadata wraps to two rows, but Home still exceeds the viewport by ~38pt — it is a scrolling feed, and at this size it scrolls. That is correct: the guarantee is that pinned screen-level CTAs — player, onboarding, review — never leave the viewport, because they sit in a non-shrinking footer. A card CTA inside a feed scrolls with its card.

CONTENT CONSTRAINTS
Seed title ≤ 60 chars, 3-line clamp. Promise ≤ 80, one line, required. Topic name ≤ 14 or the chip wraps.
Question ≤ 120. Option ≤ 70. Explanation 120–260 — shorter reads as dismissive, longer gets skipped.
Summary exactly 3 points, ≤ 90 each, each independently recallable because the scheduler asks them separately.
Reflection ≤ 600, optional, never scored, stored on-device only.
Sources ≥ 1 to publish, each with publisher, date, era marker and type.
REACT NATIVE NOTES
Logical properties only. marginStart/End, paddingStart/End, start/end — never left/right. This is what makes the LTR proof free.
Do not flexDirection:'row-reverse' inside an RTL tree — it double-flips. Plain row already lays out right-to-left.
Progress rings need react-native-svg with an explicit RTL transform; SVG does not inherit direction.
FlashList for Garden and search; fixed estimatedItemSize per card variant (list 84, rail 132, hero 300).
Player blocks render from a registry keyed by block.type with a default case. A missing key must render the fallback, not throw.
Persian numerals at the formatter, not in strings — one toFaDigits() so a Latin digit can never leak into UI copy.
LOCALIZATION
No concatenation. «۶ دقیقه» is one ICU-formatted unit, not n + ' دقیقه' — the plural rule differs by locale.
Metadata separators are components, never the character ·: in Yekan Bakh it is glyph-identical to ۰, so «۳۴ دقیقه» reads as ۳۴۰.
ZWNJ is content. Store U+200C in the string; normalise it for search, preserve it for display, and test truncation against it.
Dates: ISO UTC in data, Jalali at render. Foreign publication years carry an era marker («۱۹۸۷ م.»).
Search normalization is shared between index and query — one package, or the two drift and results become unexplainable. Colloquial variants («آسمون») are a separate curated list, not normalization.
Bidi isolation on every Latin run: emails, URLs, error codes, versions, publisher names.
ASSETS
Fonts: six loaded, four used — 400/600/700/800. 900 only in the archived before-frames; 300 loaded but unapplied. Ship four, prune Light, Thin and ExtraBlack. woff2 for web, ttf for native, already in assets/fonts. License confirmed by the product owner.
Icons: one 24×24 / 1.75-stroke vector set, ~22 glyphs, derived from the concentric-ring geometry. No icon font, no PNG sets.
Illustration: one commissioned piece per topic, 16:9 for cards and 4:5 for in-player, AVIF/WebP with JPEG fallback, three widths. Alt text is a publish gate.
Brand mark: three concentric circles plus a filled centre — never mirrored, never recoloured, never rotated. Works at 24px.
Nothing text-in-image. Every string in every screen is live text, which is what makes 200% type and screen readers work.
SUGGESTED BUILD ORDER
1 · Tokens and type primitives. Blueprint Goal 1. Nothing else lands cleanly until the violet is gone.
2 · Guest-first routing. Goal 2. Removes the login wall; biggest activation change in the set.
3 · Block registry + player. Goal 6, but bring it forward — it is where the product actually lives.
4 · Offline catalog and outbox. Goal 5. The differentiator, and it constrains the player's autosave shape.
5 · Home, Explore, search. Goal 7. Needs the card component and the reason codes to exist first.
6 · Review and growth. Goal 8. Retention, and the reason the summary block is written the way it is.
WHAT I WOULD TEST FIRST
The finite Home. Whether an ending screen with four rails feels generous or empty is the one call in this design I cannot settle from the brief. Instrument the Explore CTA at the end of the rails.
Weekly growth vs daily streak. Softer by design, and softer mechanics retain less in the short run. Watch D7 against the grace-day usage rate.
Partial credit copy. «یکی از ۲ مورد» is honest but may read as failure. Worth an A/B against a warmer phrasing that keeps the same information.
